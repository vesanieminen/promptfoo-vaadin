2 The leak fix

Run 1's problem: playwright-cli is globally installed (on PATH), so the MCP rows reached for it and bypassed the Playwright MCP they were meant to measure. The fix denies the command on the MCP rows only.

What changed: the MCP rows (playwright: 'mcp') now set disallowed_tools: ['Bash(playwright-cli:*)', 'Bash(playwright-cli)']. The provider forwards this to the SDK's disallowedTools, enforced even under bypassPermissions (the tool is removed from the model's context). A standalone probe confirmed it blocks both the bare command and the compound cd … && playwright-cli … form (Claude Code decomposes compound commands). The CLI rows are not denied — the CLI is their browser path.

Chosen over a PATH-shadow shim: declarative, no on-disk fake binary, and the blocks surface as permission_denials in the trace. Known gap: string-matching wouldn't catch a deliberate npx playwright-cli or bash -c '…' — which the agent didn't exercise.

  • n = 1 per cell — treat ±1–2 rubric points as noise. This run is the evidence: the leader flipped (MCP-led in run 1, CLI-led here) on the same A/B.
  • Self-grading. Verifier and both solvers are Claude — no cross-model anchor. Grading is mostly Playwright-measurement-based, which limits bias.
  • Residual evasion gap (unexercised). disallowed_tools matches command strings, so a deliberate npx playwright-cli or bash -c '…' would slip past. The agent didn't do either; only the 2 denied direct attempts on basic_layout occurred.
  • Token columns understate throughput by design — the out-tok figures are the real metadata.modelUsage output tokens; use cost for efficiency.
