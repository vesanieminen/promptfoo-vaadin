Skills + Vaadin MCP, Playwright via CLI, and vanilla Claude — head to head

One sweep, three Claude rows that fold two clean A/Bs into one: how the browser is driven (Playwright MCP vs Playwright CLI, all else equal) and whether the Vaadin skills + docs MCP are present (claude vs vanilla, same MCP browser). Findings: the transport A/B is an exact tie on every problem; the skills add ~4 rubric points, all on Vaadin idiom, not raw functionality; and the 480 px breakpoint bug recurs on all three.

  • Browser transport doesn't move the rubric. claude (Playwright MCP) and claude-pw-cli (Playwright CLI) are identical but for how they drive the browser, and they scored identically on every problem: 20/24, 30/31, 48/48. The CLI row did it ~26% cheaper ($17.31 vs $23.29 total) and faster on two of three solves — consistent with prior MCP-vs-CLI runs where quality tied and cost was task-dependent.
  • The skills earn ~4 points — entirely on Vaadin idiom. claude beats vanilla by +1 on basic_form (vanilla built the form with a CSS-grid Div instead of FormLayout + responsive steps, −2 idiom; net 29 vs 30) and +3 on md_ui_spec (vanilla broke the delete flow in the running app, extended FormLayout not Composite, and mixed Aura + Lumo theme variants). Both tie on basic_layout. The functionality is largely equal; the gap is how Vaadin-idiomatic the result is.
  • The 480 px breakpoint bug recurs — all three. Every row gates its stacking media query at max-width: 379.98px, so at the rubric's 480 px test the toolbar stays in row mode, overflows, and clips Button 4 off-screen. A persistent benchmark-level signal seen in every prior sweep, independent of tooling.
  • All three leak the layout-component idiom on basic_layout. Toolbars and button groups are plain Div with CSS flexbox where HorizontalLayout/VerticalLayout would be idiomatic — costing each the same Vaadin-specific point.
  • Operational note (see caveats): basic_form hit the known agent-SDK teardown hang on phase 2 — two verifier subprocesses finished their verdict then never exited and were SIGTERM'd. Their verdicts were already written to disk and are recovered here; promptfoo's own view shows those two cells as errored. One basic_form solve row (vanilla) also tripped the hang but recorded its full trace.

2 Two A/Bs in one sweep

Three rows, sharing the claude baseline, isolate exactly one variable each.

Transport  ·  claude vs claude-pw-cli

Both have the Vaadin skills + docs MCP. The only difference is the browser: claude uses the @playwright/mcp server; claude-pw-cli has no Playwright MCP and drives the browser via the playwright-cli command (its skill is loaded from a local plugin). To keep the contrast honest, the MCP row denies playwright-cli (disallowed_tools), since it's on PATH.

Result: identical rubric on all three problems.

Skills  ·  claude vs claude-no-skills

Both drive the browser through the Playwright MCP. The difference is the Vaadin help: claude loads the agent-skills plugin (15 skills) and the Vaadin docs MCP; vanilla gets neither — it's the no-help baseline.

Result: skills tie on basic_layout, win basic_form 30–29 and md_ui_spec 48–45 — every point an idiom/correctness bullet.

claude-pw-cli vs vanilla differs in two variables (transport and skills) so it isn't a clean A/B — read it only via the two cells above.

This is where the skills earn their keep: the same task, the same Playwright MCP, but the no-help baseline ships a silently-broken delete and off-idiom theming, while the skilled row is perfect.

9 Caveats & data gaps

  • Recovered verdicts on basic_form. The phase-2 verifiers for pw-cli and vanilla hit the agent-SDK teardown hang and were SIGTERM'd after writing their verdicts; promptfoo's view shows those two cells as errored. The scores here (30/31, 29/31) come from the on-disk verify-result.json files, written well before the kill. The claude verifier on the same problem exited cleanly.
  • One hung solve. basic_form/vanilla tripped the same hang during solve, but recorded its full trace and cost ($5.91) and built a working app (graded 29/31). Its inflated wall/turns reflect the wedge, not the work.
  • n = 1 per cell — treat ±1–2 rubric points as noise. The transport A/B landing on an exact tie is the strongest possible read that browser transport is rubric-neutral here, but it's still one sample.
  • Self-grading. Verifier and all three solvers are Claude — no cross-model anchor. Grading is mostly Playwright-measurement-based (the verifier observes geometry, validation and CRUD behaviour in the running app), which limits bias.
  • Transport-leak guard. playwright-cli is on PATH, so the MCP rows deny it via disallowed_tools to keep the A/B honest. The call counts confirm it held (claude: 19/12/17 MCP calls; pw-cli ~0). Residual gap (unexercised): string-matching wouldn't catch a deliberate npx playwright-cli / bash -c '…'.
  • Token columns understate throughput by design — use cost for efficiency, not the built-in token counts.
  • Screenshots: only the vanilla basic_layout row attached captures (3, above); the other rows' browser captures landed outside the attach path. The numbers come from the phase-2 verdicts regardless.
