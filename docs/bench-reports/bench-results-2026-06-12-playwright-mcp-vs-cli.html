Playwright MCP vs CLI+skills — same Claude, two browser transports

A two-row A/B isolating one variable: how the solver drives the browser. claude wires the Playwright MCP; claude-pw-cli drops it and drives the browser through the `playwright-cli` command + its bundled skill. Everything else — model (claude-opus-4-8, effort: medium), Vaadin docs MCP, the 15 agent-skills, prompt, permissions — is identical. Graded by Claude. The headline: quality is a tie, the CLI is not the token-saver it's billed as here — and the comparison partly collapsed because the globally-installed playwright-cli leaked into the MCP row.

  • Quality is indistinguishable. MCP and CLI tied on basic_layout (21/24 each); MCP took basic_form 31 vs 29; the CLI took md_ui_spec 47 vs 46. Means 94.4% vs 93.0% — inside the ±1–2 point n = 1 noise band. Switching to the CLI did not cost any solution quality.
  • The token-efficiency pitch didn't materialize. The Playwright MCP README sells CLI+skills as more token-efficient (no big tool schemas / accessibility trees in context). Here the CLI row used more output tokens on two of three problems (form 33.6k vs 26.5k; spec 51.3k vs 44.2k) and cost ~5% more overall — because playwright-cli --raw snapshot still streams an accessibility-tree YAML into context, the same verbosity the MCP has.
  • ⚠️ The transport contrast leaked — the single most important caveat. The claude row has the Playwright MCP wired and no playwright-cli skill — yet on basic_form and md_ui_spec it ran which playwright-cli, then drove the browser with 17 `playwright-cli` calls and 0 `mcp__playwright` calls. It only genuinely used the MCP on basic_layout (10 MCP calls, 0 CLI). Because the CLI binary is on the system PATH, the model reached for it regardless of wiring. So the only clean MCP-vs-CLI cell this run is basic_layout — which tied.
  • Different interaction shape where it stayed MCP. On basic_layout the MCP row made fewer, richer tool calls (10 browser calls); the CLI row issued more, smaller one-shot commands (9× open/snapshot/eval/resize) but finished faster (574s vs 730s) and cheaper ($1.65 vs $2.34) on that problem.
  • The 480px breakpoint bug recurs — both rows. Same root cause as every prior sweep: the mobile rule is gated at max-width: 379px, so it never fires at the rubric's 480px narrow test. Both lost the same two narrow-viewport bullets on basic_layout. Benchmark-level signal, not a transport difference.

8 Cross-cutting observations

Equal quality, no efficiency win

On output quality the two transports are a wash (94.4% vs 93.0%, within noise). The CLI's pitch is token efficiency, but it spent equal-or-more output tokens on all three problems and ~5% more to solve. playwright-cli --raw snapshot emits the same accessibility-tree YAML the MCP does, so the theorized context saving didn't show up here.

A global CLI binary contaminates the A/B

The biggest methodological lesson: with playwright-cli on PATH, the MCP row used it on 2 of 3 problems and never touched its own MCP there. A clean transport comparison needs the binary shadowed/removed for the MCP row. As run, only basic_layout is an honest cell — and it tied.

Where it stayed MCP, the CLI was leaner

On the one clean cell (basic_layout) the CLI row was faster (574s vs 730s), cheaper ($1.65 vs $2.34) and used fewer turns (45 vs 52) for the same 21/24. Suggestive that the CLI can be lighter on simpler tasks — but n = 1, and it reversed on the bigger problems.

Idiom is where points leak, not function

Every app worked; deductions are idiom. The 480px breakpoint bug hit both on basic_layout; both extend FormLayout rather than Composite<FormLayout> on md_ui_spec; the CLI build mis-oriented one radio group on basic_form. None of these is transport-related.

9 Caveats & data gaps

  • The transport contrast leaked (read this first). playwright-cli is globally installed and on PATH, so the MCP row used the CLI on basic_form and md_ui_spec (17 CLI / 0 MCP calls each) and only used the MCP on basic_layout. Two of three cells are therefore CLI-vs-CLI, not MCP-vs-CLI. Fix before the next run: remove/shadow playwright-cli from the MCP row's PATH.
  • n = 1 per cell — treat ±1–2 rubric points as noise. The 1.4-point mean gap is not a ranking. Re-run with REPEAT=N (and the leak fixed) before drawing conclusions.
  • Self-grading. Verifier = Claude, both solvers = Claude — no cross-model anchor. Grading is mostly measurement-based (Playwright-observed geometry / validation), which limits but doesn't eliminate bias.
  • Verify-cost asymmetry is not a transport effect. The verifier is the same Claude agent for both rows; the $14.42-vs-$9.48 verify split is driven by one expensive md_ui_spec/MCP verify row ($9.14) — verifier-side variance.
  • Token columns understate throughput by design (cache-read/creation dropped from the top-level total); the out-tok figures here are the real metadata.modelUsage output tokens. Use cost for efficiency.
  • Experimental harness. Run from the bench-playwright-mcp-or-cli branch (the playwright field + claude-pw-cli/codex-pw-cli rows). Only the two Claude rows ran; codex, codex-pw-cli, claude-no-skills, and claude-local-mcp were filtered out.
