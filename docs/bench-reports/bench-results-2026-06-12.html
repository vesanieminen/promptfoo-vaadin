The three conditions finish within 0.6 of a point on the normalized mean (no-skills 90.9% · local-mcp 90.5% · claude 90.3%), and each wins exactly one problem: local-mcp takes basic_layout (21/24), claude takes basic_form (31/31), and no-skills takes md_ui_spec (46/48). Same shape as run 3 — under a different grader.
  • Now cross-graded by Codex. Unlike run 3 (Claude-on-Claude), every grade here is from a non-Claude model, so the scores carry no self-grading bias. The flip side: the solvers ran at medium reasoning effort (run 3 used the SDK default), so the absolute level isn't comparable across the two runs — both the grader and the solver effort changed. Read this run on its own.
  • The 480px breakpoint bug recurs — a fourth straight sweep, all three solvers. Codex's verdicts independently flag it: every solver's narrow-viewport media rule fires only below ~379px, so at the rubric's 480px test the toolbar groups stay on one row and items don't grow to fill it (320/375 hold fine). A non-Claude grader confirming the same defect makes this firmly a benchmark-level signal, not an agent miss.
  • Idiom is where points leak, not function. All three apps work; the deductions are framework-fluency: on basic_layout all three build toolbars/groups from plain Div + CSS instead of HorizontalLayout/VerticalLayout; on md_ui_spec all three extend FormLayout directly rather than Composite<FormLayout>, and the email-format validation message and ConfirmDialog/theme conventions slip.
  • The SDK hang was rare this run. Only 1 of 9 solve rows hung (local-mcp / md_ui_spec, reaped at the 45-min cap, $0 recorded) — far better than run 3's 4 of 9. Its workspace still built and Codex graded it 45/48, the valid score; only its solve telemetry is lost. No verifier rows hung.

7 Cross-cutting observations

Skills/MCP still don't separate

Two sweeps in a row — run 3 (Claude-graded) and this one (Codex-graded) — put the three conditions within a point on the mean, with the no-skills baseline nominally on top each time. The durable read isn't "skills/MCP don't help" — it's that an n = 1 gap of 1–2 points is noise. Run REPEAT=N before treating any of this as a ranking.

The 480px bug reproduces (4th time)

Four independent sweeps, the same max-width: ~379px chosen by every agent, the same lost narrow-viewport bullets at 480px — and now confirmed by a non-Claude grader. This is firmly a benchmark-level signal; worth clarifying the task's narrow-viewport definition before reading the basic_layout spread as an agent skill gap.

Idiom is where points leak, not function

Every app worked; the deductions are idiom. On basic_layout all three reached for plain Div + CSS instead of HorizontalLayout/VerticalLayout; on md_ui_spec all three extend FormLayout rather than Composite<FormLayout>, and the malformed-email validation message, ConfirmDialog and theme-variant conventions slip. These are the framework-fluency points the rubric is built to catch.

Codex grading dominates the cost

Solve spend was modest and mostly intact this run ($4.58–$8.63/agent), but the phase-2 Codex verifier was the big line at ~$18–21/agent (~28.6M tokens). A cross-model grader buys bias-free scores but roughly triples the per-agent cost versus solving — budget accordingly when choosing VERIFIER=codex.

8 Caveats & data gaps

  • Codex-graded (cross-grade), not self-graded. Every verdict is from Codex gpt-5.5, so there's no Claude-on-Claude bias — but it's a single grader model, and the grading is largely measurement-based (the verifier drives the running app via Playwright).
  • Not comparable to run 3. Two variables changed at once: the grader (Claude → Codex) and the solver reasoning effort (SDK default → medium). The ~90% means here sit a little below run 3's ~93%, but that gap can't be pinned on either change alone.
  • One hung solve row. md_ui_spec/local-mcp hung (agent-SDK finished but didn't exit; reaped at the 45-min cap). The workspace was complete and Codex graded it 45/48 — the valid score — but its solve cost ($0) and trace columns are blank, so its $24.77 total and the $80.50 sweep total are understated.
  • n = 1 per cell — treat ±1–2 rubric points as noise. The single-problem "winner" flips between sweeps; don't read a ranking into it.
  • Token columns understate throughput by design — use cost, not tokens, for efficiency.
  • Screenshots are from the claude row only (the rows whose captures attach_shots.js recognized). They illustrate that row's result, not a side-by-side of all three.
